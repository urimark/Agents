FsdbDebugAgent — Architecture & Execution Flow

High-speed, persistent FSDB waveform reader and signal-tracking agent built on top of Synopsys Verdi's native C++ FsdbReader library (libnffr.so). It indexes multi-gigabyte gate-level simulation (GLS) waveforms once, hosts a shared TCP loopback session, and serves sub-second signal lookups, edge/interval queries, and ATPG pattern correlations.

Layer 1: fsdb_agent.py (Agent / CLI / MCP) Layer 2: gls_common.py & fsdb_reader_frames.py Layer 3: fsdb_reader_client.py (Protocol Client) Layer 4: fsdb_talk_server.py (TCP Loopback Proxy) Layer 5: fsdb_query.cpp (C++ Native Daemon)

3 Detailed Module-by-Module Explanation

1. Agent & Tool Server fsdb_agent.py
  • Auto-Session Management (ensure_persistent_session): Checks if a live fsdb_talk_server already exists for the target FSDB. If not, spawns one in the background and waits until indexing finishes.
  • Smart Signal Resolution (lookup_signal): Converts dotted paths to slash-separated FSDB paths, prepends the inferred top scope, attempts exact ADD, and lists sibling pins on the same cell instance.
  • Complete Signal Tracking (track_signal): Loads signal value changes, extracts initial/final values, rising/falling edges, full 0/1/x/z state intervals, and chronological transitions.
  • 3 Execution Modes: Python context manager (with FsdbAgent(...)), CLI tool, and stdio JSON-RPC MCP Server (--mcp-server).
2. Top Inference & Frame Helpers gls_common.py / fsdb_reader_frames.py
  • Top-Scope Inference (infer_top_from_verilog): Scans testbench Verilog files (*.v, *.v.gz) next to the FSDB for the wrapper module (mentor_tb) and SIM_INSTANCE_NAME (e.g. par_misc_inst) to infer mentor_tb.par_misc_inst.
  • Tessent Frame Sampling (clock_frame_code): Samples signals 1 ps before and after clock edges inside capture windows to generate 3-bit frame codes (000 steady, 010 rising pulse, 011 half pulse).
  • Glitch & X-Pulse Detection (clock_transitions): Detects intermediate x/z excursions between 0/1 edges.
3. Line-Protocol Client fsdb_reader_client.py
  • Stale-Proof Session Discovery (find_matching_session): Compares canonical realpath(fsdb_path), verifies that session.started_at >= fsdb_mtime (preventing stale reads after a re-simulation), and sends PING.
  • Client-Side Signal Cache: Caches signal_path -> (idcode, bit_size) in _id_cache and tracks loaded IDCodes in _loaded_ids so repeated queries skip redundant ADD and LOAD calls.
  • Condition Bit Encoding (_encode_target_to_bits): Converts integers, bit-strings, or ASCII strings (like "LOAD" or "LAUNCH_CAPTURE") into MSB-first bit strings for INTERVAL queries.
4. Shared TCP Loopback Proxy fsdb_talk_server.py
  • Eliminates Repeated Tree Walks: A 30–50 GB post-synthesis FSDB takes ~60–90 seconds to index its scope tree. fsdb_talk_server keeps fsdb_query open in RAM so subsequent queries complete in milliseconds.
  • Thread-Safe Serialization (DaemonProxy): Protects the daemon's stdin/stdout pipe with a mutex lock so multiple concurrent clients can safely query the same daemon.
  • Quit Protection: Rewrites client QUIT commands to PING so closing a client never kills the shared daemon; only explicit SHUTDOWN terminates the server.
5. Native C++ FSDB Query Daemon fsdb_daemon/fsdb_query.cpp
  • Fast Scope/Variable Indexing (tree_cb): Uses ffrReadScopeVarTree() to index millions of signals into std::unordered_map<string, VarInfo>, stripping vector range suffixes (e.g. [160:0]) for clean lookup.
  • Lazy Signal Loading (cmd_add / cmd_load): Queues variable IDCodes with ffrAddToSignalList() and materializes value changes in batch via ffrLoadSignals().
  • Multi-Signal Plane Sweep (cmd_interval): Evaluates conjunctive conditions across multiple signals simultaneously by advancing a min-heap / priority cursor over each signal's next transition tag (ffrGotoNextVC).
6. MCP Tools Registry JSON-RPC 2.0 stdio
  • fsdb_info: Returns FSDB path, time_scale, max_time_ns, inferred_top, and active daemon session info.
  • lookup_signal: Resolves exact hierarchical path and lists sibling pins or fuzzy wildcard candidates.
  • track_signal: Full transition, edge, and state-interval tracker over [start_ns, end_ns].
  • signal_values: Batch timestamp sampler for multiple signals.
  • list_signals & pattern_windows: Glob search and ATPG LOAD / LAUNCH_CAPTURE window finder.

4 Daemon & Proxy Wire Protocol Reference

Command Layer Request Syntax Response Format (Terminated by END\n) Underlying Verdi / Proxy Operation
TSCALE C++ Daemon TSCALE OK <scale_str>\nEND (e.g. OK 1ps) Returns scale string from ffrGetScaleUnit().
MAX_TIME C++ Daemon MAX_TIME OK <max_ns>\nEND (e.g. OK 2028764.000000) Calls ffrGetMaxXTag() and converts ticks to nanoseconds.
LIST C++ Daemon LIST [<fnmatch_glob>] OK <count>\n<path>\t<idcode>\t<bits>\n...END Filters g_ctx.vars using fnmatch(glob, path, FNM_NOESCAPE).
ADD C++ Daemon ADD <hier_path> OK <idcode>\t<bit_size>\nEND Looks up signal (exact, / prefix, or unique tail) & calls ffrAddToSignalList().
LOAD C++ Daemon LOAD OK <total_loaded>\nEND Calls ffrLoadSignals() if new signals were added since the last load.
VALUE C++ Daemon VALUE <idcode> <time_ns> OK <bit_str>\nEND (chars: 0, 1, x, z) Converts time_ns to tag, calls ffrGotoXTag() + ffrGetVC().
EDGES C++ Daemon EDGES <idcode> <a_ns> <b_ns> OK <count>\n<R|F>\t<time_ns>\n...END Walks value changes in [a_ns, b_ns] via ffrGotoNextVC().
INTERVAL C++ Daemon INTERVAL <a_ns> <b_ns> <k> (<id> <target>)... OK <count>\n<start_ns>\t<end_ns>\n...END Synchronous plane-sweep across k signals where all match target.
PING / STATUS / SHUTDOWN TCP Proxy PING | STATUS | SHUTDOWN OK pong | OK {json} | OK bye Handled by fsdb_talk_server.py for session health & lifecycle control.
